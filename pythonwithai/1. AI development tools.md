### How coding agents work
- Terminal-based coding agents like Claude Code ramped up the ascent of powerful AI-assisted development by wrapping frontier LLMs (thin LLM wrapper) with simple tools and terminal access
- **CLI** (command-line interface): (1) give LLMs file access which are sandboxed for security purposes, (2) Bash execution, where grep>RAG and (3) well-crafted tool descriptions
  - Lightweight
- **Agents**
  - Typical agent pattern: Make a plan --> execute tool-calling loop --> dispatch sub-agents for complex tasks which may bloat context window --> verify work --> summarize results
  - Can select models, independence levels and modes
  - Can clear/compact context, monitor token use
  - Can @ to mention files/folders, install custom MCP servers

### Vibe coding vs AI-assisted development
- Not reviewing any code vs human oversight in every line
- **Spec-driven development (SDD)** refers to an AI-assisted software strategy, where a spec document grounds the agent across multiple sessions
  - SDD frameworks/apps: GitHub SpecKit CLI, OpenSpec, BMAD, Cursor 2.0 --> creates detailed plans (collection of .md files) prior to AI starting work
    - Constitution (rule inviolable list) --> eg. contains stack choices and file structure
    - Greenfield projects (from-scratch) vs Brownfield
  - Spec-first vs spec-anchored vs spec-as-source
 
### Test-driven deployment (TDD)
- AI agents easily **introduce regressions (lose context)** because they struggle to maintain context over long projects; automated tests catch these before they cause problems.
- Drawback: Handwriting tests is time consuming
- Pros: AI excels at writing structured, boilerplate tests quickly, is self-healing, and update them as the application changes
    - Also gently prompt the AI model to produce more accurate output
- Visual testing tools e.g. Puppeteer MCP can be integrated with AI coding agent to look at screenshots

### Version control
- Git work trees enable an advanced technique.
- **What to do:**
  - Commit often (review diffs first)
  - Rather than debugging a complex change, it might be easier to reset, revise approach, and try again
  - Let the LLM write (verbose) commit messages, which may contain useful context for subsequent reads during debug. It explains the evolution of the codebase over time, since agents can traverse Git history.
- Pre-commit hooks: Allows LLM to write context before any code gets committed

### Git worktrees
- Create multiple directories corresponding to different branches, allowing agents to work in parallel without interference
- Opening multiple agents, with each doing a different task = parallel agents
- In large repos, this can speed up work --> running on different directories, but sharing same git history

### Context management
- Context engineering focuses on assembling prompts from documentation, tool descriptions, memory files, domain knowledge, and conversation hx, requiring curation to avoid bloat
- **Why is this important?**:
  - LLM performance degrades as context windows fill
  - Only the best information is passed onto the model
  - The optimal context length usually much shorter than model's listed window (even if advertised as large ~200k) --> misled by unnecessary context
- **How can this be done:**
  - Documentation: Fetch, Context7 MCP, compiling yourself (in a md file, saved to your document's repo)
  - Memory
    - /new and /clear on per-task basis
    - Remove unneeded MCPs esp. when not needed for human conversation
    - Keep only vital information in memory.md; delegate specialized info to other files (Claude.md or agents.md should not contain design instructions, it should guide agent to find this within another .md)
  - Tools are described concisely, but not too briefly to ensure proper output.
  - Output: Ensure they do not bloat context window when too verbose.
- **Managing long contexts:**
  - Subagent can be designed and dispatched to read documentation, summarize, and bring back to primary agent --> occurs in a different window
  - Compacting history to preserve only important context
  - Externally indexed note-taking
